### 2. 自进化调研（Agent Workflow Memory / ACE）

**来源**：[ACE: Agentic Context Engineering, arXiv 2510.04618](https://arxiv.org/abs/2510.04618)｜[Agent Workflow Memory, ICML 2025](https://proceedings.mlr.press/v267/wang25bx.html)｜[Dynamic Cheatsheet, arXiv 2504.07952](https://arxiv.org/abs/2504.07952)

三条方法，三种判断：

**① AWM（Agent Workflow Memory）——采纳。** 方法一句话：把**成功轨迹整体抽象成可复用的多步工作流**，而不是只记零散的单点教训。这一条正好切中本仓的真实形态：LEDGER 里 19 条教训全是**点**，而"选题→成稿→草稿箱"这条已经跑通两次的**链**，从来只存在于每场会话的临时记忆里——下一场得把 L-011（跨仓 worktree）、L-012（WebP）、L-016（force 早退）在脑子里重新串一遍才能复原全程。

落地（政策层直改）：`LEDGER.md` 新增 **`## 可复用流程`** 段，与单点教训分开存放，写入第一条 **[W-F01] 每日文章链路**——7 步，每步带命令和**失败信号**（例如第 6 步"图片数 0 = WebP 老坑复发"）。规矩是**只写已跑通 ≥2 次的链路**，避免把一次性的运气写成流程。原论文的向量检索层砍掉：本系统条目数是两位数，全量读入即可（Dynamic Cheatsheet 那条正好验证了小规模下"全量塞入不做检索"是有效形态）。

**② ACE（delta 追加 + 有效性计数器 + 非 LLM 确定性合并）——本场不采纳，但记下触发条件。** 它解决的是"playbook 长到每次 LLM 整篇重写会磨掉细节"（context collapse）。这个隐患对本仓是**真的但尚未发生**：STRATEGY 只有 6 条策略，每场全量读入，还没观察到任何一条被无意改写或稀释。现在就上 id + 计数器 + 合并规则，是为想象中的规模付结构成本。**触发条件写在这里**：当 STRATEGY 策略数 >12，**或**出现第一次"某条策略/教训被会话无意删改或稀释"的实例，就引入 ACE 的 delta 机制。（不采纳的理由不是"不好"，是"还没到"。）

**③ Dynamic Cheatsheet——已等价存在，无需引入。** STRATEGY.md 本质就是那份 cheatsheet。这条的价值是反向的：它证明"没有向量库"不是本系统的短板，是小规模下的正确形态。

### 3. T-012 选题入口脚本化

s2 的交接第 3 条点名："别每天靠子 agent 现查库路径"。落成 `system/pipeline/pick_topics.py`。

实测：

```
$ python3 system/pipeline/pick_topics.py --date 2026-08-14
[跳过] workspace/topics/2026-08-14.md 已存在（会话可能已补写角度判断）。要重生成加 --force   RC=1

$ python3 system/pipeline/pick_topics.py --date 2026-08-15
✓ workspace/topics/2026-08-15.md（主候选 3 + 备选 8，库 200 条，已排除 6 键）        RC=0

$ grep -c "8217a19b0eb9\|51b992b41e05\|f8b53600dd3a" workspace/topics/2026-08-15.md
0        ← 今天用过的三条，明天不会再出现
```

设计上刻意的一条分界：**脚本只做机械部分**（定位库、解析 frontmatter、按 `talk_id#question_idx` 排除往期用过的、按 importance 排序、把回溯字段抄全），**"选哪条、什么角度"仍归会话**。理由是这一步的成本结构：查库路径每天付一遍纯属浪费（s2 花了 2 分钟），而判断"哪条能接上一手素材"恰恰是每天不同、且脚本做不了的。

**一个如实的局限**：importance 高分条目里技术/科学类偏多——08-15 自动选出的 3 条主候选有 2 条是"生态数据 AI"和"太空数据中心"，明显不适合本号。**纯分数排序 ≠ 选题适配**。没有强行给脚本加内容判断（那会变成用关键词黑名单假装懂选题），改为把备选池从 5 条放宽到 8 条，让会话有替换余地。

### 5. 纠正一个错：s2 立策略 6 时那条 grep 是有偏的

践行策略 6 复核指标时，先看了一眼原始行——发现 s2 用的 `grep -o '｜[^｜]*｜\*\*'` 只能匹配**正文带 `**` 加粗**的条目，把早期未加粗的 L-001~L-005（清一色 `打法`）整批漏掉了，还混进了"→ 调整："之类的无关行。按类别字段精确重算：

```
$ grep -oE '^\[L-[0-9]+\] [0-9-]+ ｜[^｜]*' LEDGER.md | sed 's/.*｜//' | sort | uniq -c
   8 打法      4 错误→打法      4 错误      2 规律      1 错误→规律
```

19 条里非错误驱动 **10 条 = 52.6%，本来就过半**。s2 算出的"20%"不成立，"这个账本只在摔跤时学习"这个立论的数字依据随之作废。

处理：策略 6 **保留**（成功入账、写适用条件仍然是对的，且它促成了本场的 L-019），但**指标改掉**——从"占比升到 ≥35%"（既基于错数、又已经达标、还没有驱动力）改为"**此后每条新增打法必须写明适用条件**，`grep -c '适用条件' LEDGER.md` 随新增打法同步增长"。STRATEGY 策略 6 已就地标注更正，LEDGER 补 **L-020**。

一般化的那句记在 L-020：**从数据得出的结论，其可信度上限是那条取数命令的正确性**——而取数命令通常没有测试、没有对照、写完就当事实用。当时本该察觉的信号是：账本有 19 条条目，统计却只数到 10 条。

### 6. 本场的打法入账（策略 6）

**L-019：新判定标准先对存量数据回跑一遍，再宣布它生效。** 适用条件写清了：任何新增的自动判定（验收标准、健康检查、告警规则、质量门）接入生产前，必须先对历史数据回跑并检查结果分布**不是全 0 或全 1**。今天检查器回跑得到"1 通过 1 不通过"，正是这个一半一半证明它有判别力；若全过或全不过，说明写的是恒真/恒假的伪标准，接进仪表盘后会以"验收正常"的面目长期骗人（同 L-010）。

至于 s2 挂起观察的那条候选打法（"跨仓 push 后核对对方工作区"）：本场没有跨仓操作，无新增观察，**继续挂起**，不为凑数入账。
