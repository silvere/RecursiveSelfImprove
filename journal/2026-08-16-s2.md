### 1. 开场告警是假的，而假告警遮住了真问题

逐条查证：

| 告警内容 | 实际 |
|---|---|
| 上一场非零退出 rc=1 | **假**。s1 日志尾行 `=== 退出码 0 2026-08-16 01:38:20 ===` |
| 上一场没写 journal | **假**。`journal/2026-08-16-s1.md` 存在 |
| 工作区有 4 处未提交改动 | **假**。s1 已提交（`94b72a3`），开场 `git status` clean |
| 排班缺口 11 小时 | **假**。s1 与本场相隔 6 小时，正常 |

四条全假，因为它们描述的是 **08-15 evening 那场**——`workspace/session-runs.log` 的末行至今仍是它，s1 一行都没落。

根因当场证实：`git show f5fd556:system/run.sh | grep -c record_run` → **0**。s1 启动于 01:30，加载的是 `f5fd556` 版本的 run.sh，那时 `record_run` 这个函数还不存在——它是 s1 自己在会话中新写的。**新代码只对下一场生效**，这是本仓第三次踩它（T-018 改看门狗时踩过、并明写了"改动对下一场起效"；s1 在 journal 里引用过这句话，然后当场又踩了一次）。

真正被遮住的问题是：**"根本没启动"和"启动了但没能收尾"在只记结束的日志里长得一模一样**，而这两种情形的正确恢复动作恰好相反（前者重做，后者必须先抢救工作区）。s1 的设计用 `journal_written`/`dirty` 两个字段区分了后两种失败，唯独没覆盖"连记录都没有"这一种。

### 2. 修法（政策层直改 `system/run.sh`）

- **`record_run` 增加 `phase` 字段**：开场落 `phase=start`（位置在 `session_alert` 读完末行之后、启动 claude 之前，否则它会读到本场自己那一行），收尾落 `phase=end`。有了 start，"末行"才恒等于"最近真正启动过的那一场"。
- **`session_alert` 新增判据**：末行 `phase=start` ⇒ 上一场被硬杀（kill -9／断电／休眠），连退出码都没留下，属硬丢场。
- **`dirty` 告警改为与当前工作区求交**：上一场遗留的改动若已被后续场次提交，如实降级为"现已提交，无需抢救"的说明行。今早误报里最费时的就是这一条——它让本场差点去抢救一堆早已提交的东西。
- **按日志实证补记 s1 的运行记录**（`rc=0/jw=1/dirty=0`，时间取自日志的 `退出码 0 01:38:20`），与 s1 回填 08-15 两场是同一做法。

**改法本身值得记一笔**：`run.sh` 正在运行，故用「复制到临时文件 → 改 → `mv` 覆盖」而非原地 `Edit`——`mv` 换的是 inode，运行中的 bash 仍持有旧 inode，字节偏移不受影响。

**五场景实测（抽出生产函数体当场跑）**：空记录 → `✓ RC=0`；正常 end → `✓ RC=0`；**末行 phase=start → 报"只开场未收尾" RC=1（新判据）**；复刻 s3 尾行且工作区仍脏 → "…且现在仍有 N 处" RC=1；同一尾行但在 clean 仓库上 → 降级为"现已提交，无需抢救" RC=1。替换后 `bash -n` 通过；补记后 `bash system/run.sh selfcheck` → **`✓ 上一场运行记录正常` RC=0**。
