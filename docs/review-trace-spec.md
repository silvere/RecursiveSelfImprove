# 审稿痕迹归档规范

GOAL v2 验收第 2 条要求"任一篇可从成稿回溯到选题"。此前 `gen_dashboard.py` 的 C2
只检查审稿记录字段**指向的路径存在**——空目录、占位文件都能通过。本规范把"可溯源"
落成可执行判定。

## 1. 存放位置

一篇文章的全部痕迹放在 **`~/Code/AIWriter2/articles/<YYYY-MM-DD-slug>/`** 一个目录里，
不散落。RSI 仓库不复制副本，只在 LEDGER 记路径（避免同一事实两处存放而漂移）。

## 2. 最小三件套（缺一即不可溯源）

| 证据 | 文件 | 最小内容要求 |
|---|---|---|
| 选题依据 | `01-brief.md`（或 `00-topic.md`） | 出现 `talk_id` / `source_url` / 「选题」/「来源」之一，能指回 wtqn 条目或当日 `workspace/topics/*.md` |
| 论点竞技场结论 | `03-arena.md`（或 `02-arena.md`） | ≥200 字符实质内容：胜出论点及其淘汰对手的理由 |
| 七刀审稿记录 | `06-review.md`（或 `05-review.md`） | 出现「必修」/「驳回」/「刀」之一，即每刀的处置结论 |
| 终稿 | `final.md` | 存在即可 |

每个文件均要求 **≥200 字节**——空文件与"没写"不能共用一个通过结果（同 L-010）。

## 3. LEDGER 记法

`## 文章产出记录` 段每行第 4 段（审稿记录）**填文章目录路径**，不填单个文件、不填说明文字。
格式：`日期 ｜标题 ｜选题来源 ｜<文章目录绝对路径> ｜草稿箱：成功/失败 + media_id`。

未走七刀的文章照实记（写清缺什么），检查器会判为不可溯源并在仪表盘 C2 里点名——
**如实不合规优于粉饰合规**。

## 4. 检查方式

```bash
python3 system/pipeline/review_trace.py --ledger          # 检查 LEDGER 记录的每一篇
python3 system/pipeline/review_trace.py <文章目录>         # 检查单篇
```

退出码 0 = 全部可溯源。`gen_dashboard.py` 的 C2 直接调用同一函数，
命令行结论与仪表盘结论不会出现两套口径。

## 5. 当前实测状态（2026-08-14 s3）

```
✗ 2026-08-14 审稿记录字段里没有文章目录路径（会话直写，未走七刀）
✓ 2026-08-13 /Users/jingweisun/Code/AIWriter2/articles/2026-08-08-hobby
可溯源 1/2 篇
```

即：**"每天一篇"的连续性正在推进，但"每篇过七刀"的质量口径已经破了一次**。
补救方向不是回填一份假的审稿记录，而是让 T-013 的 `run_daily.sh` 把七刀作为必经步骤，
产不出三件套就不算当日完成。
