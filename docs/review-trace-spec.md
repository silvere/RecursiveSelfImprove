# 审稿痕迹归档规范

GOAL v2 验收第 2 条要求"任一篇可从成稿回溯到选题"。此前 `gen_dashboard.py` 的 C2
只检查审稿记录字段**指向的路径存在**——空目录、占位文件都能通过。本规范把"可溯源"
落成可执行判定。

## 1. 存放位置

一篇文章的全部痕迹放在 **`~/Code/AIWriter2/articles/<YYYY-MM-DD-slug>/`** 一个目录里，
不散落。RSI 仓库不复制副本，只在 LEDGER 记路径（避免同一事实两处存放而漂移）。

## 2. 最小三件套（缺一即不可溯源）

| 证据 | 文件 | 最小内容要求 |
|---|---|---|
| 选题依据 | `01-brief.md`（或 `00-topic.md`） | 出现 `talk_id` / `source_url` / 「选题」/「来源」之一，能指回 wtqn 条目或当日 `workspace/topics/*.md` |
| 论点竞技场结论 | `03-arena.md`（或 `02-arena.md`） | ≥200 字符实质内容：胜出论点及其淘汰对手的理由 |
| 七刀审稿记录 | `06-review.md`（或 `05-review.md`） | 出现「必修」/「驳回」/「刀」之一，即每刀的处置结论 |
| 终稿 | `final.md` | 存在即可 |

每个文件均要求 **≥200 字节**——空文件与"没写"不能共用一个通过结果（同 L-010）。

## 2.1 证据刀的固定第一步：数字盘点（2026-08-16 pm 补，落 L-023 的欠账）

`06-review.md` 的证据刀**必须以一份数字清单开头**，之后才谈引用来源对不对。做法：

1. 把初稿正文里的**所有阿拉伯数字与序数词**逐个列出（含"第 15 座""十四次""约 1080 条"这类）；
2. 对每一个只问一句：**这个数是数出来的、算出来的，还是从一句比喻里顺出来的？**
3. 凡答案是第三种，一律降级为定性表述（比喻可以留，但要明写是打比方）；答案是前两种的，补上口径来源。

**尤其针对"从自己上一篇作品里引用数字"**——自引最容易跳过验证：你记得那句话，但不记得那句话当时是不是数据。

为什么排在证据刀第一位：数字一进入文本就自动获得可信度，而它的来源传抄一次就消失了，
且**没有任何读者能发现**——它看起来太具体了，具体到不像编的。实例见 L-023
（`2026-08-15-falsification/06-review.md` 第三刀必修 3：修辞里的序数词"15"被推导成"重复过十四次"，
而未完成项目数从未被统计过）。同类复发见 08-16 篇（"出了三次事"与账本 13 条错误条目矛盾）。

## 2.2 审稿规则库：每一条必修都要变成下一篇的检查项（2026-08-17 s2 新增）

**问题**：七刀每天都产出"必修 N 处"，但这些必修**只作用于当篇**，第二天审稿又从零开始凭感觉找。
于是同一类硬伤反复出现：修辞数字冒充统计数字已复发 3 次（L-023 / 08-16 篇 / 08-17 篇），
相对时间算错基准已复发 2 次（08-16 篇的"三天前"、08-17 篇的"九天前"）。

**依据**（08-17 s2 自进化调研，见当日 journal）：*Self-Improving AI Coding Agents Through
Accumulated Behavioral Rules*（arXiv 2607.13091）——把每一条被采纳的评审意见固化成**持久行为规则**，
规则集在真实部署中从 5 条长到 18 条，agent 能自检的错误类别随之单调扩大。本仓已有一个现成的
对照实验：2.1（数字盘点）是**唯一一条被固化下来的审稿规则**，而它落地后的第一篇（08-17）
就当场抓出 **6 个**不合格数字——固化一条的收益，远大于每天重新凭感觉审一遍。

### 规则库（只增不减，编号不复用）

| 规则 | 内容 | 立规依据 |
|---|---|---|
| R-01 | **数字盘点**：正文每个阿拉伯数字与序数词逐个判"数出来的／算出来的／从比喻里顺出来的"，第三种一律降级为定性表述 | 2.1；L-023 |
| R-02 | **相对时间必须写出基准并当场做减法**："五天前"要写明相对哪一天、被减数是什么。凭印象写相对时间是本仓复发率最高的错法之一 | 08-16 篇"三天前"实为当日凌晨；08-17 篇"九天前"实为五天前（误把今天当基准） |
| R-03 | **引用一字不改，标点也算**：外部引语与他人原话须与源文件逐字比对，不得为通顺加减逗号 | 08-17 篇给审计员原话加了一个逗号 |
| R-04 | **举例数字不得升格为全集数字**："出了三次事"若只是举了三个例子，就不能写成总数 | 08-16 篇（与账本 13 条错误条目矛盾） |
| R-05 | **单次经验不得写成"每次／总是／从来"** | 08-16 篇"每次都写"实为一次 |
| R-06 | **无一手来源的专有名词宁可降级为限定描述**：药名、人名、机构、产品版本号，记得住不等于查证过 | 08-17 篇主动不点药名，改写为"原本给器官移植病人抑制排异的老药" |

### 可判定指标

1. 每篇 `06-review.md` 的证据刀段必须含一份**规则库复查清单**，R-01 起逐条给出"本篇是否命中"的结论；
   缺这份清单即视为本规范未执行。
2. 本篇查出的、**不属于现有任何一条 R 的**必修项，当场在上表追加为新规则并写立规依据——
   审稿发现只允许"沉淀"或"归类"，不允许"用完即弃"。
3. 反向体检：`grep -c '^| R-0' docs/review-trace-spec.md` 的值应**单调不减**，且每次增长都能在
   当日 journal 找到对应的必修项。若连续 3 篇文章 0 增长且这 3 篇都有必修项，说明规则 2 未被执行。

## 3. LEDGER 记法

`## 文章产出记录` 段每行第 4 段（审稿记录）**填文章目录路径**，不填单个文件、不填说明文字。
格式：`日期 ｜标题 ｜选题来源 ｜<文章目录绝对路径> ｜草稿箱：成功/失败 + media_id`。

未走七刀的文章照实记（写清缺什么），检查器会判为不可溯源并在仪表盘 C2 里点名——
**如实不合规优于粉饰合规**。

## 4. 检查方式

```bash
python3 system/pipeline/review_trace.py --ledger          # 检查 LEDGER 记录的每一篇
python3 system/pipeline/review_trace.py <文章目录>         # 检查单篇
```

退出码 0 = 全部可溯源。`gen_dashboard.py` 的 C2 直接调用同一函数，
命令行结论与仪表盘结论不会出现两套口径。

即：**"每天一篇"的连续性正在推进，但"每篇过七刀"的质量口径已经破了一次**。
补救方向不是回填一份假的审稿记录，而是让 T-013 的 `run_daily.sh` 把七刀作为必经步骤，
产不出三件套就不算当日完成。
