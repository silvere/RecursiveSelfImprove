# 阅读数据回流通道

## 为什么是人工抄录

`docs/data-return-feasibility.md` 实测：同一 access_token 下 `cgi-bin/draft/count` 返回 200，
而 `datacube/*`、`freepublish/*` 全部返回 `48001 api unauthorized` —— 凭证有效、链路通畅，
唯独数据类权限位没开。要打开必须完成微信认证，而**微信认证要求企业/组织主体**。

**2026-08-17 08:49 人经飞书答复：「个人。」** → 个人主体订阅号无法认证，
**此路永久封死，与工程投入无关**。这是该结论从"待确认"变为"已验证"的那一步。

## 怎么填

`wechat-reads.csv` 每篇文章一行，脚本负责补前 4 列（成稿时自动追加），
后 5 列由人填 —— 打开公众号后台，一篇抄一个数，5 篇约 1 分钟：

| 列 | 谁填 | 说明 |
|---|---|---|
| `date` / `slug` / `title` / `media_id_prefix` | 系统 | 成稿入草稿箱时写入，可回溯到 LEDGER 产出记录 |
| `published` | 人 | `y`/`n` —— **草稿箱里的稿子如果一篇都没点发布，阅读数恒为空，这条验收标准永远无法验证** |
| `reads` / `likes` | 人 | 后台数字，抄下来即可；未发布的留空 |
| `recorded_at` | 人 | 抄录日期（YYYY-MM-DD），用来判断数据新鲜度 |
| `note` | 任一方 | 异常说明 |

## 判定口径（刻意从严）

`gen_dashboard.py` 的 C4 **不认"文档存在"**，只认这张表里**至少有一行带实测 reads**。
理由见 W-008 / T-024：验收标准被系统自产的文档点亮，已经发生过 2 次。
一份没有任何真实数字的通道文件，是通道，不是数据 —— 它不该让 C4 亮绿灯。

## 待校准假设（数据到位后按顺序验）

> 这一段的存在意义：C4 不是一个勾，它是内容改进链路唯一的校准源。
> 下面每条都是"现在无法判定、但只要表里有若干行实测 reads 就能开始判"的问题。
> 新增假设时写清**它要对比的两组是什么**，否则数据来了也不知道怎么用。

1. **情绪弧线方向**（2026-08-22 s3 登记）｜来源：Temple Fox / *Information Systems Research*（Mudambi、Kumar、Srivastava、Ghose），[报道](https://now.temple.edu/news/2026-02-18/new-study-reveals-how-keep-readers-attention-digital-age)——受控操纵叙事性 / 情绪弧线方向 / 语言复杂度三特征，结论是三者有交互：**复杂语言只在"高叙事性 + 情绪由坏到好"时才不掉读者**。
   - **为什么与本号相关**：本号文章稳定落在"高复杂度"那一格（论点密集 + 大量精确数字），三个特征里情绪弧线方向是唯一从未被看过一眼的。
   - **要对比的两组**：已发布文章按结尾是否收束到一个可执行的正向动作分成两组，比较阅读数中位数。
   - **判定前提**：≥6 篇有实测 reads（低于此不下结论，样本量不够）。
   - **不采纳为写作规则的理由**：在零反馈时按它改写作规则，只是换一个没有证据的信念（STRATEGY 策略 10/11）。
